# CLAUDE.md — Achilles Documentation Repository

## Project Overview

**Achilles** (v0.3.0) is a Sphinx-based documentation landing page for the Achilles physics simulation collaboration. The repository generates a static HTML landing page that provides versioned navigation to the full Achilles documentation, which is deployed to GitHub Pages.

**Authors:** Joshua Isaacson, William Jay, Alessandro Lovato, Pedro A. Machado, Luke Pickering, Hayden Piwonka, Noemi Rocco, Noah Steinberg

## Build System

This repository uses **Sphinx** to generate HTML documentation from reStructuredText (RST) sources.

### Install dependencies

```bash
pip install -r requirements.txt
```

### Build locally

```bash
# Linux/macOS
make html

# Windows
make.bat html

# Direct sphinx-build invocation
sphinx-build -b html . _build/html
```

Output lands in `_build/html/`. Open `_build/html/index.html` in a browser to preview.

### Clean build artifacts

```bash
make clean
```

## Sphinx Configuration (`conf.py`)

Key settings:

- **Project:** `Achilles`, release `0.3.0`
- **Theme:** `sphinx_book_theme` with SVG logo from `../assets/logo.svg`
- **Favicon:** `../assets/favicon.ico`
- **Extensions:** `breathe`, `sphinxcontrib.bibtex`, `sphinx_design`
- **Bibliography:** `src/references.bib`
- **Templates:** `_templates/`
- **Static files:** `_static/`
- **Excluded patterns:** `_build`, `Thumbs.db`, `.DS_Store`

### Version management

`conf.py` reads `versions.json` at build time and injects the version list into `html_context`. The landing page's JavaScript (`index.rst`) fetches this JSON at runtime to populate the version dropdown. If `versions.json` is absent, the versions list defaults to empty (`[]`).

---

## Landing Page (`index.rst`)

The landing page provides:
1. A "Go to Documentation" button linking to `latest/index.html`
2. A version selector `<select>` dropdown populated via `fetch('versions.json')`
3. JavaScript that maps each version to `<version>/index.html`

The `latest` entry in `versions.json` is displayed as "Latest Release" and is pre-selected.

## CI/CD Pipeline

**File:** `.github/workflows/landing.yml`

**Trigger:** Pushes to the `landing_page` branch only.

**Steps:**
1. Checkout code
2. Set up Python 3.x
3. `pip install -r requirements.txt`
4. `sphinx-build -b html . _build/html`
5. Deploy `_build/html` to the `gh-pages` branch using `peaceiris/actions-gh-pages@v4`

> **Important:** The CI/CD pipeline only triggers on the `landing_page` branch. Development work happens on feature branches and `master`; only `landing_page` branch content is deployed.

## Development Workflow

1. **Make changes** on a feature branch (not directly on `landing_page` or `master`).
2. **Test locally** with `make html` and verify `_build/html/index.html` renders correctly.
3. **Commit** with clear, descriptive messages.
4. **Open a PR** targeting `master`, then merge `master` → `landing_page` to trigger deployment.

## Key Conventions for AI Assistants

- **No compiled code:** This repository contains only documentation source files (RST, Python config). There are no C++, test suites, or build artifacts to manage.
- **Do not commit `_build/`:** Build artifacts are always gitignored and regenerated by CI.
- **`versions.json` is external:** It is fetched at runtime by the deployed site, not stored in this repo. Do not create a stub `versions.json` in this repo.
- **Assets are external:** `../assets/logo.svg` and `../assets/favicon.ico` are referenced relative to the Sphinx source dir and expected to exist in a sibling `assets/` directory at deploy time.
- **RST formatting:** Use standard reStructuredText conventions. Heading underline characters follow the order `=`, `-`, `~`, `^`, `"`.
- **Sphinx extensions:** When adding new RST features, check whether the required extension is already listed in `conf.py` before adding it to `requirements.txt`.
- **Python style in `conf.py`:** Follow PEP 8. Keep configuration values grouped by their Sphinx section comments.
- **Branch protection:** Never push directly to `gh-pages` — it is managed exclusively by the CI/CD action.
